The review workflow in six steps

  1. Read the four documents above. Step 1 (Start Here) is the most important; the others can be referenced as you work.
  2. Open chapter 01 in Editorial mode. Read the chapter end-to-end first, without taking notes. Get a feel for the chapter's framing.
  3. Open the per-chapter scholar packet for chapter 01 — scholar_review/pending/01_waking_up.review.md. The packet's §10 contains the structured response template for that specific chapter. (You can use either the per-chapter §10 template or the cross-chapter review_feedback_template.md — whichever you prefer.)
  4. Walk the checklist from mufti_review_checklist.md, ticking items as you go. Mark anything that fails.
  5. Record corrections in the feedback template — one block per item. Specify the HID, the issue type, the current wording, your suggested correction, severity, and verdict.
  6. Repeat for chapters 02, 03 (wudu only), 10. Then mark the overall batch verdict at the end. Return the file to the project via file drop, email, or any other agreed channel.

What you absolutely should not be asked to do.
If any packet asks you to approve a fabricated narration, a softened fiqh translation, an implicit-fatwa framing, or a chapter quietly stripped of NEEDS SCHOLAR REVIEW tags — please refuse and notify the project. The system is built to make those asks impossible, but no system is perfect.

A smaller, fully-verified book is better than a larger book with even one fabricated narration.
